# 生产交接指南

## 能力边界

| 能力                       | 当前代码状态                                                | 交付方仍需验证                                     |
| -------------------------- | ----------------------------------------------------------- | -------------------------------------------------- |
| 微信登录、手机号           | `auth.ts`、`wechat.ts` 已接入专用路由                       | 双应用凭据、真机授权、退出与过期                   |
| 地图、短信                 | `service-routes.ts` 调用 `integrations.ts`                  | 真实地图查询、签名模板、验证码及费用限制           |
| 订阅消息                   | 用户意愿登记、管理员受控发送、去重已实现                    | 微信模板权限及真机接收                             |
| 房源核验                   | 人工登记和生产发布门槛已实现                                | 材料、业主授权、机构登记及审核责任                 |
| 图片                       | 上传按配置选本地或私有 S3                                   | 真实桶权限、条件写入、访问与恢复                   |
| 微信支付                   | 仅下单请求构造、签名、验签、通知解密工具                    | 订单、收款、回调业务路由、入账、退款、对账均未完成 |
| 实名、自动核验、VR、智能锁 | 未完成身份证/人脸服务、地方平台自动核验、真实 VR 与硬件控制 | 不得对外承诺接通；人工审核不等同于自动认证         |

查询 `GET /api/integrations/status`；旧 `GET /api/providers` 以 307 重定向到此路径。状态中的支持、配置和 `liveVerified` 是不同概念，配置成功不能证明真实调用成功。

## 环境文件

本地将 [.env.example](../.env.example) 复制为私密 `.env`。现有 `dev:api`、`start`、`build:mini`、`account:role` 自动读取，`npm run dev` 会启动该接口命令。不要覆盖已有秘密。

生产使用 [deploy/.env.production.example](../deploy/.env.production.example) 的私密副本 `deploy/.env.production`；Compose 按 `env_file` 注入，详见[部署说明](../deploy/README.md)。可选服务完全不用时省略整组变量，**不要取消注释后留空**：集成与 S3 模块会对部分配置报错。

### 基础、身份和发布

| 实际变量                                    | 用途与要求                                                                |
| ------------------------------------------- | ------------------------------------------------------------------------- |
| `NODE_ENV`                                  | 开发、测试或生产；生产不生成演示种子并拒绝演示数据库                      |
| `HOST`、`PORT`                              | 默认开发回环、生产全网卡，端口 4310；公网暴露必须受防火墙和代理限制       |
| `DATA_DIR`                                  | 生产必须为绝对持久化路径；包含数据库及本地上传                            |
| `BACKUP_DIR`                                | 备份脚本输出根目录；默认 `backups`                                        |
| `WECHAT_OWNER_APPID`、`WECHAT_OWNER_SECRET` | 业主小程序凭据，生产必填                                                  |
| `WECHAT_AGENT_APPID`、`WECHAT_AGENT_SECRET` | 经纪人小程序凭据，生产必填                                                |
| `PUBLIC_APP_URL`                            | 生产有效 HTTPS 根地址；不能代替来源白名单                                 |
| `CORS_ORIGINS`                              | 逗号分隔精确 HTTPS 来源，不带路径或末尾斜杠                               |
| `DEFAULT_AGENT_ID`                          | 实际存在且启用的正式经纪人；未设时需显式选择合法经纪人                    |
| `WECHAT_CONTENT_CHECK`                      | 生产内容提交要求精确设置 `true`，并具备真实微信文本安全权限               |
| `OPERATOR_NAME`、`SUPPORT_EMAIL`            | 运营者名称与支持渠道；生产检查要求填写，需与隐私文案一致                  |
| `PRIVACY_VERSION`                           | 隐私版本，默认 `2026-09-09`；服务端与小程序构建一致，版本不同登录返回 409 |
| `MINI_MODE`                                 | 构建默认生产；根模板配置为演示 `demo`                                     |
| `MINI_API_BASE_URL`                         | 小程序接口源；生产为无路径、无凭据的真实 HTTPS 地址                       |
| `TLS_CERT_DIR`                              | Compose 使用的宿主证书绝对目录，含证书链和私钥                            |
| `QIAN_ENV_FILE`                             | Compose 选择接口环境文件；部署脚本与 `--env-file` 保持一致                |

生产两端应用编号、秘密和公开地址由配置模块校验；元数据还需通过 `check:production`。秘密只留服务端，不能进入小程序包、浏览器构建、日志或交接 ZIP。

### 地图、短信和订阅

| 实际变量                                           | 用途                                                |
| -------------------------------------------------- | --------------------------------------------------- |
| `TENCENT_MAP_KEY`                                  | 腾讯地图服务端密钥                                  |
| `TENCENT_SMS_SECRET_ID`、`TENCENT_SMS_SECRET_KEY`  | 腾讯云短信调用凭据                                  |
| `TENCENT_SMS_APP_ID`                               | 短信应用编号                                        |
| `TENCENT_SMS_SIGN_NAME`、`TENCENT_SMS_TEMPLATE_ID` | 已审核签名及单验证码参数模板                        |
| `TENCENT_SMS_REGION`                               | 当前允许 `ap-guangzhou`、`ap-nanjing`、`ap-beijing` |
| `TENCENT_SMS_SESSION_TOKEN`                        | 使用临时凭据时的可选会话令牌，常规凭据不设置        |
| `WECHAT_SUBSCRIBE_TEMPLATE_ID`                     | 微信订阅模板编号；需对应实际应用权限                |
| `WECHAT_SUBSCRIBE_TITLE_FIELD`                     | 模板标题字段，默认 `thing1`，只接受 `thing` 加数字  |

### S3 对象存储

| 实际变量                                   | 用途                                       |
| ------------------------------------------ | ------------------------------------------ |
| `S3_REGION`、`S3_BUCKET`                   | 区域及私有桶                               |
| `S3_ACCESS_KEY_ID`、`S3_SECRET_ACCESS_KEY` | 最小权限访问凭据                           |
| `S3_ENDPOINT`                              | 兼容存储指定 HTTPS 源端点；AWS 可省略      |
| `S3_FORCE_PATH_STYLE`                      | 可选 `true` 或 `false`，按厂商寻址方式设置 |

未设置任何 S3 变量时使用本地上传。设置后上传完成才记录成功；不确定结果返回 `UPLOAD_UNCONFIRMED`，保留记录供核对，不连续重传。读取先经过应用图片访问控制，再重定向到短期预签名链接。桶不能公开，链接是短期持有者凭证，不得写日志或长期保存。

### 支付工具参数——不启用收款

实际读取 `WECHAT_PAY_APP_ID`、`WECHAT_PAY_MCH_ID`、`WECHAT_PAY_SERIAL_NO`、`WECHAT_PAY_PRIVATE_KEY_PEM`、`WECHAT_PAY_API_V3_KEY`、`WECHAT_PAY_NOTIFY_URL`、`WECHAT_PAY_PLATFORM_PUBLIC_KEYS_JSON`。整组校验公钥映射和密钥格式；即使全部有效，也没有订单和回调业务路由，不能开放收款或佣金结算。

## 账号准备与开通顺序

1. 准备两个小程序的主体、管理员、真实应用凭据、HTTPS 域名、隐私说明及适用平台资质；填写运营者与支持联系方式。开通文本内容安全权限。
2. 腾讯地图申请服务端密钥与出口限制；短信申请账户、签名和单验证码参数模板；订阅消息申请标题字段匹配的模板。S3 准备私有桶、最小权限和版本/备份策略。
3. 在正式小程序登录，任何新账号都先是 `owner`。两端按 `AppID + openid` 隔离，不按手机号或 `unionid` 自动合并。
4. 经纪人绑定微信手机号，向 `POST /api/agent-applications` 提交姓名、机构、执业资料、城市和绑定号码。管理员审核通过后升级为经纪人并进入目录；两端通过目录协作。
5. 受控服务器终端核对目标 UUID 与生产数据目录后授权首个管理员：

```powershell
# UUID 替换为已核实的真实用户编号
npm run account:role -- UUID admin --confirm
```

当前镜像已包含编译后的角色脚本，容器维护使用 `node scripts/set-role.js UUID admin --confirm`，通过部署负责人确认的 Compose 执行上下文连接同一数据卷。不要在无 tsx 的运行镜像直接调用开发版 npm 命令。

角色变更撤销旧会话。管理员重新小程序登录，`POST /api/admin/pairing` 生成八位、六十秒有效码；浏览器通过 `POST /api/auth/admin/pair` 一次性消费。正式浏览器仅配对登录，无默认密码或自选角色登录。

## 业务接入与人工发布要求

| 流程 | 路由与关键要求                                                                                                                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 微信 | `POST /api/auth/wechat/login` 提交 `app/code/privacyVersion`；手机号走 `POST /api/auth/wechat/phone`                                                                           |
| 地图 | 登录后调用 `GET /api/map/geocode` 或 `/api/map/search`，未配置不伪造结果                                                                                                       |
| 短信 | `POST /api/sms/challenge` 需 `consent:true` 且已有微信绑定号码；六位码、五分钟有效/发送冷却，最多五次验证；`POST /api/sms/verify` 成功后不能重用                               |
| 订阅 | 查询 `/api/subscriptions/template`，用户主动授权后 `POST /api/subscriptions/grant`；管理员调用 `POST /api/notifications/:id/deliver`，按通知去重，超时保留未知结果而非自动重发 |
| 图片 | `POST /api/uploads` 发送 PNG/JPEG 原始字节，最大 5MiB，不用 multipart；按配置写本地或 S3                                                                                       |

人工房源核验与发布按以下顺序执行：

1. 管理员核实房源资料、业主委托授权、机构登记与材料来源；证件和私人材料不得放进公开房源字段。
2. `PUT /api/property-checks/:id` 提交 `verified`、`authorizationConfirmed`、`code`、`agencyRegistration`、`note`；系统记录审核人和时间，写入审计。管理员可用 GET 同路径查询。
3. 材料通过时两个确认字段均应为 `true`，编号及说明要对应可追溯证据，禁止仅为通过发布而勾选。
4. 再按房源状态流转调用 `PATCH /api/properties/:id` 发布。生产缺少核验或授权确认返回 409 `PROPERTY_CHECK_REQUIRED`。
5. 生产内容提交还要求 `WECHAT_CONTENT_CHECK=true` 并通过文本安全接口；这不替代人工图片、权属和授权审核。
6. 授权撤销、资料变化或争议出现后，管理员应更新核验并主动下架/复核。不能假设修改核验标志会自动撤下已经发布的房源。

这是已实现的人工核验工作流，不是地方住建平台自动核验或身份证人脸认证。

## 部署与发布

1. 填生产环境文件，使用全新持久化目录/卷；生产拒绝已有演示数据库，不能删掉演示身份后冒充迁移完成。
2. `npm run check:production` 只检查配置和文件，不外呼；可选服务完全未配置也可能通过格式检查，仍需逐项验收。
3. 按 [deploy/README.md](../deploy/README.md) 配置证书、域名和 Compose。API 不映射宿主端口，只有 nginx 开放 80/443；`-CheckOnly` 也会构建镜像与运行检查容器。
4. 确认代理来源、限频、日志脱敏、图片保护、重启持久化。生产默认监听全部网卡，宿主直接启动时必须另设访问控制。
5. 真机验收双端登录、手机号、入驻、配对、内容安全、人工发布、地图、短信、订阅、上传；支付仍不得开启。
6. 记录版本、配置版本、责任人、脱敏测试证据和回滚点；运营、安全、隐私、运维及业务负责人按职责确认。

当前只有本地验证记录。Docker 不在当前 PATH，容器构建、HTTPS 握手及真实厂商调用未验证。

## 备份、恢复、回滚与打包

- `npm run backup` 使用 SQLite 备份接口，随后复制本地 `uploads`；该命令目前不自动读取 `.env`，需显式注入正确 `DATA_DIR/BACKUP_DIR`。暂停写入与上传后备份，才能保证数据库和图片同一业务时间点。
- S3 对象不在本地备份内，必须另有版本、复制或快照；保存数据库对象键与对应对象版本清单，验证可恢复。
- 恢复到新的独立目录，校验 SQLite 完整性、业务记录与图片引用，不混入旧 WAL/SHM。恢复旧会话和删除记录时需重新落实撤销/清理；原数据保留到负责人批准清理。
- 应用回滚用兼容版本及配置，数据库不兼容则执行已演练恢复并评估写入损失。支付/短信/订阅的外部行为不会随数据库回滚撤销，未知结果先核对。
- 命名卷不得用 `down -v` 删除。备份加密、异地保存、到期清理和恢复演练需要运维落实，现有脚本不包办这些能力。
- `scripts/package-handover.ps1 -OutputDirectory <输出目录>` 生成 ZIP 和 SHA-256，按清单排除真实环境文件、数据库、上传文件及依赖缓存。检查源码/静态资源未夹带真实资料后交付。ZIP 不是数据库或对象存储备份。

## 故障排查

| 现象                     | 优先检查                                                                |
| ------------------------ | ----------------------------------------------------------------------- |
| 配置报错                 | 是否部分启用了服务变量、把可选变量置空、秘密/公钥格式错误；只看脱敏错误 |
| 隐私版本冲突             | 服务端与小程序的 `PRIVACY_VERSION` 一致后重建，重新阅读授权             |
| 登录或手机号失败         | 双端应用编号、秘密、真机凭证、接口权限；不切回演示身份绕过              |
| 生产内容被拒绝           | `WECHAT_CONTENT_CHECK`、真实微信会话、内容安全权限和返回结果            |
| 房源不能发布             | 人工核验记录、两个确认字段、审核资料和合法状态流转                      |
| 短信/订阅结果未知        | 流水与持久化状态，先核对，不重复发送或绕过冷却/去重                     |
| S3 上传未知或图片失效    | 上传记录、对象键、桶权限、条件写入支持、签名有效期；不公开桶或连续重传  |
| 来源/限流错误            | HTTPS 来源精确匹配、代理设置及同一代理出口限流                          |
| 健康检查成功但能力不可用 | 查询集成状态，再做对应受控业务测试；配置检查不是远端验收                |
