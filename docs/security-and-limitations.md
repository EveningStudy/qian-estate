# 安全、隐私和数据留存

## 当前控制与边界

微信身份按应用隔离，新用户为业主，经纪人经审核进入目录。管理员终端授权会撤销旧会话，浏览器仅通过一次性配对登录。服务器检查身份、角色、对象归属及状态，客户端隐藏按钮不构成安全边界。

生产内容提交要求微信文本安全；人工房源核验和授权确认是发布必要条件。人工核验已经实现，但不等于自动权属认证、身份证人脸认证或合同网签。智能锁没有硬件控制。支付仅工具函数，没有可用订单和回调业务。

地图、短信和订阅已接业务路由。短信只向绑定号码发送，用户需确认，限制有效期与尝试；订阅以用户意愿、服务端既有通知和去重记录受控发送。未知结果要核对，不循环重发。

S3 桶保持私有，上传经结构校验及随机键控制；短期链接仍是持有者凭证，不能记录日志。图片结构检查不是完整解码、恶意软件扫描或权属审核。

## 隐私要求

填写 `OPERATOR_NAME`、`SUPPORT_EMAIL`、`PRIVACY_VERSION` 并与用户所见说明一致。隐私版本必须同步到小程序构建与服务端。姓名、电话、房源地址、消息、证件材料及精确位置按目的最小化收集，不因手机号授权而默认同意营销或实名处理。

资料导出与注销申请已有接口；注销返回待处理不代表已经删除。应由负责人核实未结业务、依法保留事项、申诉和实际删除结果。证件原文不放入公开房源或图片目录。

密钥、验证码、登录凭证、预签名链接、完整手机号和消息不得进入日志、截图、仓库或交接包。检查源码和静态资源，不能仅依赖打包目录排除。

## 留存和恢复

当前有会话过期、退出撤销、短信有效期及订阅发送记录，不存在已完成的全量业务自动删除承诺。留存期限需按业务目的和责任要求确定，落实定时任务、访问控制、到期清理和验证。

| 数据                       | 处理要求                                            |
| -------------------------- | --------------------------------------------------- |
| 会话、短信挑战             | 到期拒绝并安排周期清理；记录不含明文验证码          |
| 消息、预约、客户、人工核验 | 明确目的、保留期限、删除入口和审核例外              |
| 幂等、订阅发送             | 保留覆盖重试窗口的证据，不能清理后导致重复外呼      |
| 日志与测试证据             | 最小化、脱敏、限权、到期清理                        |
| SQLite 和本地图片备份      | 加密、异地保存、共同恢复演练                        |
| S3 对象                    | 单独版本/备份与删除策略；本地备份脚本不包含对象数据 |

恢复旧备份后要重新落实已批准的注销、撤销和删除。数据库回滚不会撤销短信、订阅或真实支付，保留外部流水核对。发生泄露先限制访问、撤销凭据、保护必要证据，再由负责人处置，不删除数据库或日志掩盖问题。
